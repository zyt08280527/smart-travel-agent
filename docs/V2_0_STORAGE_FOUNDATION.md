# V2-0 第一阶段：版本化业务存储

状态：2026-10-22 已实现并通过隔离数据库测试，尚未切换现有 Web/Agent 保存链路。此前工作区、高德迁移及历史采用的提交基线为 `d1958aa`。

## 本阶段解决的问题

checkpoint 保留的是 Agent 执行上下文，旧 JSONL 仅保存批准后的单段摘要。V2 需要独立的业务行程和可追溯版本，并在存储查询时强制检查归属，才能继续建设登录、多用户保存与多站点。

本阶段新增 `domain/trip.py`、`services/trip_repository.py` 与 `services/legacy_trip_migration.py`。不自动初始化或修改现有运行数据；迁移必须显式调用工具。

## 数据与版本

| 记录 | 职责 |
| --- | --- |
| `trip_owners` | 本地归属身份 ID、显示名称、创建时间；不是登录凭证 |
| `trips` | owner_id、schema_version=2、当前版本号、标题、业务时区及创建/更新时间 |
| `trip_revisions` | 不可变的内容快照、连续版本号、创建原因与时间 |
| `legacy_trip_imports` | 旧 ID、归属、目标行程、源文件及记录摘要，保证重复导入不新增行程 |
| `trip_schema_migrations` | 数据库结构迁移版本及应用时间 |

业务内容版本为 2，当前 SQLite 结构迁移版本为 1，两者职责不同。数据库使用独立的 `application_id`；空库可以初始化，已有同版本库可重复打开，其他用途或更高版本的库拒绝修改。

本轮仅支持 `single_leg` 内容，尚未实现多站点规划或行程生命周期：

- `planning`：保存完整 `TravelComparisonResult`，包含已有候选、所选方式/公交候选、推荐、路线快照时间及路线几何。
- `transit`：保存 `TransitPlan` 及明确的选中候选索引。
- `legacy_summary`：原 `SavedItinerary` 摘要，保留旧 ID 与保存时间，不补造轨迹、候选或多站点。

费用、轨迹、时间依据只保存原类型已支持的字段，不表示第三方数据已刷新。业务时区默认 `Asia/Shanghai`，显式值须为有效 IANA 时区。

## 读写与并发

`get/list/revisions/revise/adopt` 都要求显式归属；单个行程的读取、历史查看和修改按 `owner_id + trip_id` 查询。归属不匹配与行程不存在使用同一异常，先检查归属，再检查版本冲突。

创建行程同时写入第 1 版；修改和采用旧版都新增版本。采用第 1 版时，可以生成内容相同但原因是 `adopted` 的第 3 版；原第 1/2 版不改写。SQLite 触发器阻止直接更新/删除版本；用户数据删除和清理策略尚待后续专门实现。

写入使用 `BEGIN IMMEDIATE` 事务与调用方的 `expected_revision`。两个进程同时修改第 1 版，只允许一个写入第 2 版，另一个返回版本冲突。历史内容、当前版本指针及标题在同一事务内提交，异常时整体回滚。文件及 SQLite 操作通过线程执行，不阻塞异步事件循环。

这是存储层归属检查，尚不是 HTTP 鉴权。现有 API、会话、checkpoint 与 MCP 保存还没有接入上述归属边界，不能据此声称全应用已具备多用户隔离或允许公开访问。

## 旧 JSONL 导入

入口：`scripts/migrate_legacy_trips.py`。必须显式提供源文件、目标库和归属 UUID。默认只读检查，不建库、不创建归属身份、不生成备份。下列 UUID 只是文档示例，不代表现有用户。

```powershell
.\.venv\Scripts\python.exe scripts\migrate_legacy_trips.py --source data\itineraries.jsonl --database data\trips.sqlite --owner-id 12345678-1234-5678-1234-567812345678
```

只有增加 `--apply` 才初始化目标库、创建指定的归属身份并执行导入。确认源数据、目标路径和归属后再执行；本轮没有对真实文件应用此命令。

导入会：

1. 检查 UTF-8、有效记录、无效行号与重复旧 ID；存在无效行或重复 ID 时拒绝应用，不静默丢弃记录。
2. 创建 `源文件名.v1-源文件摘要前16位.bak`，保留读取时的原始字节并刷盘。已有同名备份须内容完全一致，不覆盖旧备份或源文件。
3. 在同一事务导入整批记录。相同旧 ID、内容和归属再次导入会跳过；旧 ID 的内容或归属冲突时整批回滚。
4. 输出文件摘要、有效数、创建数、跳过数及备份路径。回滚或失败后备份可能仍保留，不能将备份存在视为导入成功。

`TRIP_STORAGE_PATH` 已加入配置与示例，供下一阶段接入运行时；离线工具要求显式 `--database`，不依赖模型或高德密钥。默认路径下的业务数据库和 JSONL 迁移备份已加入 Git 忽略规则；其他自定义数据目录须由操作者管理。

原 Web/Agent 链路继续使用旧存储，当前没有双写或自动回滚切流机制。旧文件与数据库是独立副本，后续切换前仍须完成一致性核对和备份恢复演练。
