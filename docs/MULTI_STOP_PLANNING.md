# 固定顺序多站点：候选选择与路线编排

2026-10-22：已在领域时间推演之后，接通相邻路线查询、有限候选组合与偏好筛选。当前仍是后端服务，未接 MCP/Agent、API、网页、多段地图或多段保存；本轮没有请求真实高德或模型。核心功能优先，上线准备继续后置。

## 链路与入口

```text
MultiStopRequest（已确认地点、城市编码、顺序、时间、偏好）
  → MultiStopPlanningService.plan
  → 仅查询相邻地点的步行/公共交通/允许时的驾车
  → LegCandidates（保留所有返回候选和失败分支）
  → select_multi_stop_plans
  → evaluate_fixed_order（每个组合的完整时间线与硬限制）
  → 仅对可行组合排序，返回有限方案和明确推荐 ID
```

业务模块：`services/multi_stop_selection.py`、`services/multi_stop_planning.py`；领域输入/输出在 `domain/multi_stop.py`。已有时间窗定义与 UTC 推演规则继续见 [时间推演说明](MULTI_STOP_TIMELINE.md)。

路线服务复用现有高德驾车、步行、公共交通适配器。公共交通候选保留 `TransitOption` 的原始分段、线路及几何；步行/驾车保留 `RoutePlan` 的步骤、时间依据、费用字段和几何。每条候选附来源与查询完成时间，服务不编造缺失数据。

驾车总费用保持未知，过路费与出租车估价分字段保留，不当作私家车全程费用；驾车接驳步行保持未知。步行全段距离是步行距离，费用为 0。公共交通每条候选单独规范化，不先选一个代表路线。

## 有限搜索和预算

地点顺序不变，只组合每一相邻分段的路线候选。默认每段上限 8 个、总组合上限 4096，返回前 3 个方案（可请求 1–10 个）。预算内所有组合都检查，不用单段局部最优替代完整行程筛选。

单段候选超过上限或乘积超过预算时，抛出明确预算异常，不静默截断，不将尚未搜索到的方案标记为不可行。空候选段返回 `insufficient_data`，没有推荐方案。重复候选 ID、错序分段或不匹配的起终点 ID 属于输入错误。

对每个组合复用时间推演与全程硬限制，只有 `feasible` 可以进入推荐。返回已检查数、可行数、明确拒绝数及数据不足数；问题计数按实际问题出现次数统计，同一组合可以有多个问题。保留有限问题示例，不输出所有失败组合的完整轨迹。

如果所有组合都明确违规，返回 `infeasible`；没有可行组合但仍有数据不足的组合，返回 `insufficient_data`，不能声称现实中绝对无路可走。存在可行组合时只在已验证集合中推荐，并说明其他组合可能因数据不足未参与。

## 确定性偏好

比较全程总耗时（含等待与停留）、完整已知费用、累计步行和分段内部换乘数。复用单段 `PRIORITY_WEIGHTS` 的四项权重，去掉尚未接入的天气项并重新归一化；总耗时/费用/步行/换乘越小，该项得分越高。分值是本次候选集内的规则分，不是学习模型或独立质量指标。

| 偏好 | 本阶段规则 |
| --- | --- |
| 综合推荐 | 四项加权比较 |
| 时间优先 | 提高总耗时权重 |
| 省钱优先 | 完整费用已知的组合优先，再按费用偏重的综合分排序 |
| 少步行 | 总步行已知的组合优先，再按步行偏重的综合分排序 |
| 少换乘 | 总换乘已知的组合优先，再按换乘偏重的综合分排序 |
| 地铁优先 | 在完整可行组合中优先包含地铁的分段数更多的组合，再按综合分比较 |

硬限制始终先于偏好。两段地铁合计步行违反上限时，可以选择只有一段地铁的可行组合；没有可行地铁组合时明确说明按综合偏好回退。

未知费用不当作 0。省钱优先且所有完整费用都未知时，回退综合偏好并明确无法按费用比较；少步行/少换乘在全部对应指标未知时也回退。没有完整费用数据时，已知费用小计仍不等于总费用。

总分相同后按预计总耗时及候选 ID 稳定排序；先规范候选顺序，因此仅改变供应商候选数组顺序不改变相同输入下的排序结果。方案 ID 是请求与所选路线快照的内容摘要；新查询时间或请求变化可以产生新 ID，不是持久化业务版本号。

## Provider 编排

仅查询相邻站点，不构建全点对矩阵；默认每段请求一次步行、一次公共交通和一次驾车（明确不能驾车时跳过驾车）。公共交通默认请求 3 个候选，向供应商传递当前统一偏好派生的策略。

默认全次规划最多 12 个路线服务调用，共用 3 个并发槽，每个已开始的调用最多 30 秒；预算在发起调用前检查。这里的服务调用数不包含底层城市解析/坐标转换等 HTTP 请求。供应商若返回超出实际搜索预算的候选，选择器明确报错，不悄悄丢弃。

单种方式失败或超时保留为失败分支，继续比较其他真实返回的路线；所有分支不可用时不生成虚构方案。异常文本可能含供应商请求地址或 Key，因此只返回通用失败说明；取消请求会传播取消，不包装成降级成功。CPU 搜索在线程运行，不阻塞异步事件循环。

所有分段耗时仍来自查询时快照。当前没有按组合推演出的各段未来出发时刻重新获取路况/班次，也未做逐段天气适配；不能宣称未来公交一定运营或准点。首次请求不使用或覆盖现有单段会话状态，不读写真实行程文件。
