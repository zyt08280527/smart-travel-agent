# 多站点正式交互与本地保存闭环

2026-10-23。固定顺序多站点已从计算服务接入 MCP、FastAPI 和正式网页。当前代码支持地点确认、时间/限制编辑、完整方案选择、单段切换、多段地图、保存和重开；自动化通过，尚未进行真实供应商和桌面/手机浏览器端到端验收。不能据此标记 V2-1 全部验收完成或已上线。

## 用户流程

1. 顶部选择“多站点行程”，输入搜索城市、起点、1–3 个中间点及终点。每个地点都先搜索，再由用户点选确认，不自动采用首个同名结果。
2. 填写明确出发时刻、中间点停留、可选到达时间窗与最终截止；所有网页时间按北京时间输入/显示。六项偏好与驾车、累计步行、累计换乘限制进入同一请求。
3. 规划成功后展示完整方案。系统推荐和当前选择分别标注；点击其他完整方案只改变当前选择，不改偏好。
4. 地图展示各段已有轨迹与所有站点，突出当前查看段。某段没有轨迹时保留站点和缺失提示，不补画站点间直线冒充路线。
5. 可单独选择某段的其他候选。后端复用可信草案候选，重新推演全程并校验限制；无效组合拒绝采用，页面保留原方案。有效组合生成新草案，系统推荐不因手动选择改写。
6. 修改地点、时间或偏好后，旧方案保留并提示需重新规划，此时不能保存旧方案为新设置的结果。更新失败不清空原结果；旧异步响应不能覆盖刚打开的新草案。
7. 点击“确认保存当前完整行程”，在一次确认中检查地点顺序和预计到达后保存。随后从“已保存多站点行程”重开，保留原选择和快照，不自动查询新路线。重新规划生成新草案，不覆盖已保存记录。

网页用正式高德适配器查询，不是固定数据验证页。开发测试通过注入模拟服务覆盖上述流程，没有新发起真实路线或模型请求。网站当前运行进程是否已加载新代码须在真实联调前检查，不沿用旧 PID 或健康检查快照作结论。

## API 与可信数据边界

| API | 行为 |
| --- | --- |
| `GET /api/places?query=...` | 真实地点查询入口；返回 POI ID、WGS84 坐标及统一城市编码 |
| `POST /api/multi-stop/plan` | 验证结构化多站点输入，查询/筛选后保存可信草案，返回草案 ID 与结果 |
| `GET /api/multi-stop/drafts/{id}` | 读取原草案，不刷新路线 |
| `POST /api/multi-stop/drafts/{id}/select` | 只接收各段候选 ID，依据服务端原候选重新推演和选择 |
| `POST /api/multi-stop/drafts/{id}/save` | 只接收所选方案 ID，服务端从可信草案提取完整快照 |
| `GET /api/multi-stop/itineraries` | 返回本地已保存多站点快照，支持重开 |

保存接口不接受客户端提交耗时、轨迹或任意完整行程；草案不存在、选中 ID 不在可行方案中或多传业务数值会被拒绝。重复保存相同草案和同一方案返回同一记录，避免重复点击产生副本。选择未出现在前三名的有效分段组合时，保留原推荐，额外展示用户所选组合，分值仍依据同一完整候选集计算。

地点城市编码按 POI 的行政区编码规范化，缺少城市信息时不开放点选；请求也检查各站编码一致。这是结构化输入约束，服务不额外核实任意调用者伪造的坐标所属城市，真实联调仍需覆盖同名点/跨城点及供应商缺失字段。

## MCP 与聊天

新增 `plan_multi_stop_trip`，由规划 MCP 服务提供。需要先确认全部地点、明确出发时刻和必要停留/时间窗；允许同时指定明确出发和最终到达限制。它只生成草案，不保存。

Agent 收到结果后通过 `multi_stop` 结构化卡片提供页面入口；新多站点结果会进入多站点页面，不把更早的单段路线当成当前结果。单段到达路由、偏好快照与推荐解释的快捷分支避开已识别的多站点上下文。模型若误用单段 `save_itinerary` 保存多段，grounding 中间件会阻止并引导到完整行程保存入口。

代码配置与 2026-10-23 实际运行的 `/health` 均为 10 个工具。真实模型已完成三站规划及停留修改的两轮样例，详见下文；这不代表同名点澄清、所有多轮表达或错误解释已经全面通过。

## 本地存储

本轮为核心功能添加独立本地 SQLite 草案/已保存快照存储，配置 `MULTI_STOP_STORAGE_PATH`，默认 `data/multi_stop.sqlite`，已加入 Git 忽略。规划 MCP 子进程显式透传环境中的路径覆盖值。

该库仅服务当前单机多站点功能，不接账号或用户隔离，不迁移原 JSONL，不接管 V2-0 的业务版本库。旧单段保存仍沿用原审批与 JSONL 链路。不能把该本地闭环称为多用户产品或公开上线准备完成。

`frontend/src/MultiStopWorkspace.tsx` 独立维护表单、草案和选择，会话缓存恢复不依赖聊天卡片位置；`MultiStopMap.tsx` 绘制多段几何。`services/multi_stop_workspace.py` 持久化不可覆盖的草案/保存快照，重新选择或规划通过新草案表达。当前没有多站点记录删除/保留期限管理，这些后续补齐，不声称已覆盖完整生命周期。

## Agent 地点澄清检查（2026-10-23）

`MultiStopPlaceClarificationMiddleware` 在多站点规划工具真正执行前检查已搜索地点。针对坐标可匹配的搜索证据，如果查询有多个合理候选，按站展示候选地址、城市编码和原始 attribution，保留调用消息 ID 但清除工具调用并结束本轮。模型不能仅凭自己已经填入一个候选就免于澄清。唯一精确名称可继续，模型填入的城市/POI 标识与同坐标搜索结果冲突则阻止规划。
