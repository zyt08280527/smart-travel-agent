# 本版状态与功能边界

截至2026-10-25，本版核心功能已基本满足用户需求，进入文档与演示收尾。没有创建发布版本、Git提交或部署。本文描述当前工作区；历史设计与进度中的旧待办状态，以最新实施记录为准。

## 功能清单

| 功能 | 当前实现 | 验证状态 |
| --- | --- | --- |
| 统一对话与右侧结果 | 单段、多站点在同一对话处理；目的地推荐通过弹窗收集条件 | 自动化覆盖；用户简单试用反馈基本满足需要 |
| 单段出行 | 高德地点澄清、驾车/步行/公交、六种偏好与硬限制、地图、手选、审批保存 | 本地回归；已有真实供应商/交互阶段记录，未覆盖所有自然语言 |
| 手选稳定性 | 手选只更新选中、地图与保存目标，不把候选移到首位；新规划可改变排序 | 后端/组件回归；不将每种设备的每次切换算作全面实测 |
| 多站点 | 同城固定顺序、1–3个中间点、停留/时间窗/截止、完整分段、选择、确认保存重开 | 自动化覆盖；本次自然语言遗漏末站修复后用户简单复测无问题 |
| 可选时间 | 无时间时计算相对总耗时；具体时间窗、截止及守护需要明确时间 | 自动化覆盖；不编造到达日期或公交班次 |
| 目的地推荐 | 三馆区中计算起点→一个馆区→起点，按费用/时长/限制筛选，显示事实来源与未知项 | 本地回归；不是开放景点搜索或任意兴趣推荐 |
| 推荐连续对话与历史 | 有限条件修改、冲突澄清、排除/恢复候选、版本保护、服务端历史重开 | API/服务/组件回归；不等于任意自由问答都有完整模型记忆 |
| 设备定位 | 主动授权、地址/精度/时间确认后替换起点，推荐与后续路线沿用同一坐标 | 用户明确反馈该链路验收通过；固定坐标真实高德解析通过；未据此宣称所有设备通过 |
| 行程天气 | 按站点预计到达小时采样，推荐可选择不查、提示或排除信号/未知 | 模拟供应商与API/组件验证；不是全程实况或官方预警 |
| 出发前守护 | 新完整单段记录/多站点保存后主动开启，持久化检查、重试、租约恢复、取消 | 自动化覆盖；完整真实定时触发/重启链路没有用户逐项验收记录 |
| 站内提醒 | 两类行程统一显示、已读持久化、旧结果令牌保护、只读预览、主动新对话规划 | API/组件回归；不自动覆盖或保存新方案，无外部发送 |

## 验证证据

- 最近一次代码回归：后端607项、前端84项；Ruff、前端lint和生产构建通过，存在1项既有Starlette弃用警告。测试数是当次记录，本轮仅更新文档，没有重跑或据此增加性能结论。
- 自动化主要使用固定/模拟模型、定位、路线和天气响应，验证规则、状态与交互；不能换算成真实服务成功率。
- 真实外部证据包括过往路线/地图联调，以及本轮固定深圳坐标的高德转换和地址解析成功。具体范围查阅阶段文档，不把旧的8条行为评估成绩当成当前新增功能的验收结果。
- 用户反馈“简单测试下来没问题，大致满足需要实现的功能”；设备定位到推荐、路线链路另有明确“验收通过”。均为本次使用反馈，没有补造测试设备、样本数或未反馈的专项结果。

## 已知限制

1. 尚未公开上线，没有账号认证与应用级数据隔离。当前共享本地业务数据，不能称为多用户生产服务；版本化存储基础也没有完成真实数据切流。
2. 路线是查询时快照，公交没有实时车辆位置、到站或指定未来班次保证；费用未知不能解释为免费。推荐是确定性约束/评分，不是训练出的推荐算法。
3. 多站点固定顺序、同城，不做自动重排、跨城和停车换乘。目的地推荐固定三个深圳馆区，未扩展兴趣/同行者适配；缺少指定日期开放核验，预约和营业仍须核实。
4. 天气只覆盖起终点或逐站到达采样小时，无法代表沿途、全部等待或停留时段；未知与失败不会被当作正常或安全。
5. 守护默认出发前30分钟窗口检查一次，失败5分钟后重试，最多三次尝试；依赖后端运行和外部接口，存在队列/网络延迟。过期停止，终态暂不重新开启。只有站内结果，无邮件/浏览器推送，不自动采用路线。
6. 旧单段摘要没有可信坐标时须重新规划保存才能开启守护；旧版仅本地推荐缺少原条件时须重新确认，不能从摘要反推完整状态。
7. 定位不保证来自GPS。当前在推荐弹窗按需获取一次，需授权和安全环境；深圳外、精度超过500米或无法定位时手动选点，不持续跟踪。移动后不会自动刷新，须重新定位、确认并推荐。
8. 模型、网络和供应商可能失败，用户反馈过的连接错误并不能保证永不再现；没有把完整压测、配额保障、手机适配和所有异常专项标为完成。
