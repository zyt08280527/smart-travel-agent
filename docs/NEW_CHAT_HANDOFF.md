## 3. 当前架构与业务链路

React + TypeScript + Vite → FastAPI（NDJSON 流式）→ LangChain create_agent / LangGraph → MCP 工具 → 外部服务。

- 模型：Qwen 接口；具体型号读取配置，不在交接中固化。
- 地点：直接使用高德 POI；不再是 Nominatim 主查。
- 路线：高德驾车、步行、公共交通；公共交通包含公交车与地铁等，并非仅公交车。
- 地图：高德 JS API；旧存 WGS84 路线转换为 GCJ02 后绘制。前端 JS Key 与后端 Web 服务 Key 不同。
- 天气：目前仍为 Open-Meteo。高德天气迁移尚未完成，尤其不能把按天预报说成小时预报。
- Graph checkpoint、会话历史使用 SQLite；行程仍是本地存储，不能冒充已完成多用户数据库产品。
- 新增多站点后代码工具配置为 **10 个**，规划 MCP 注册已测试；此前 `/health` 返回 9 个是历史快照，本轮未重启并核对实际健康响应。

主流程：用户描述 → 缺必要信息则追问 → 地点解析/确认 → 综合规划并发获取天气与三种路线 → 硬限制过滤 → 偏好规则推荐 → 流式结构化卡片 → 当前行程工作区 → 用户选具体路线 → 保存审批/可信快照校正 → 已保存行程查看/重新规划。

综合规划内部已获取天气，不应让模型再重复调用天气工具。推荐是确定性规则，不是训练出来的推荐模型。

### 当前行程工作区

- `frontend/src/currentJourney.ts` 独立管理 thread 级当前行程；不再通过改写首条消息卡片维护当前状态。
- 电脑左对话/右行程；手机使用“对话 / 当前行程”标签。完整路线卡、候选和地图集中工作区，聊天只给变化说明与查看入口。
- 会话缓存、历史恢复、异步返回边界已有测试；普通文字或天气回复不应清空当前路线。
- 历史会话、已保存行程折叠展示。完整历史版本入口、采用旧版仍未完成。

### 单层偏好与独立限制

- 六项单选：综合推荐、时间优先、省钱优先、少步行、少换乘、地铁优先。删除“通用偏好 + 公共交通高级偏好”双层 UI。
- 独立限制表单：驾车条件、最大步行米数、最大换乘次数，支持设置和清除；到达截止时间仍通过对话设置。
- 先硬限制，再候选选线及跨方式推荐。可行地铁存在时，地铁优先推荐该地铁，即使驾车更快；没有可行地铁时解释回退。
- `priority` 是主偏好，旧 `transit_strategy` 仅用于迁移兼容及派生高德查询提示。
- 旧主偏好 balanced 且有具体旧策略时提升旧策略；明确非 balanced 主偏好优先。切回 balanced 时清旧策略。
- 历史卡片不会仅因打开页面自动重新计算；新一轮调整后使用新规则。

### 当前选择 ≠ 系统推荐

- `selected_plan_id` 与 `recommended_plan_id` 分开。
- 公交 `selected_transit_candidate_index` 与 `recommended_transit_candidate_index` 分开。
- 手动选择非推荐路线不应改偏好，也不应篡改系统推荐；地图和保存跟随当前选择。
- 顶部交通方式按钮会选用该方式首个候选，并非单纯筛选；具体候选可直接点击。
- 测试已验证“系统推荐地铁，用户选公交，保存公交”的数据链路。
- 偏好变化有效快照可重排；过期或特定公交策略变化会触发刷新。仅刷新公交分支的优化仍待做，不能说所有偏好调整都零外部请求。
