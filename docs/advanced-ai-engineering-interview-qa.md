# AI 应用开发进阶面试问答

本文整理自面试题截图，重点覆盖 Agent、RAG、LangGraph、多 Agent、安全、评测、AI Coding
与工程可靠性。回答遵循“为什么用 → 怎么实现 → 收益与边界”的结构。

## 使用原则

- **项目真实做过：** 智能出行 Agent 的 LangGraph、MCP、HITL、SQLite checkpoint、工具调用、
  行为评测、Trace；RAG 项目的 Chunk、Embedding、Milvus、阈值过滤、引用和确定性拒答。
- **了解但未落地：** Reranker、Agentic RAG、Redis、多 Agent、A2A、Planner/Critic、国产 MLU。
- 面试时对第二类问题应说“当前项目没有实现，我的设计会是……”，不能说成已有线上经验。

## 一、Agent 基础与范式

### 1. Flow、ReAct、Plan-and-Execute 有什么区别？

- **Flow：** 开发者预先规定步骤和分支，执行路径基本确定。优点是稳定、可测、成本可控；缺点是
  难以处理开放任务。
- **ReAct：** 模型循环执行“观察上下文 → 决定动作 → 获得工具结果 → 再推理”，适合步骤数量和
  工具选择不确定的任务，但必须设置步数、成本和错误上限。
- **Plan-and-Execute：** 先由 Planner 生成计划，再由 Executor 逐步执行，适合长任务和可并行子任务；
  代价是额外模型调用，且计划可能过时，需要重规划机制。
- 我的出行 Agent 更接近受约束的 ReAct：模型动态选择工具，LangGraph 管理循环，保存操作由 HITL 拦截。

### 2. LangChain Chain 与 LangGraph 状态机本质区别是什么？

- Chain 更像函数组合或固定数据流，输入经过若干 Runnable 后得到输出，适合线性和较稳定的流程。
- LangGraph 把执行表示为“状态 + 节点 + 边”，可以循环、条件跳转、暂停、恢复和持久化。
- 复杂 Agent 不能只靠纯 Chain，是因为下一步取决于模型 tool call、工具结果、错误、审批和历史状态，
  执行路径不是固定直线。
- 简单的文档摘要或固定 RAG 链仍应优先使用 Chain，不应为了使用框架而强行上状态图。

### 3. AI 工作流和 Agent 的边界在哪里？什么时候用固定 DAG，什么时候用状态图？

- 输入输出和步骤依赖确定、错误分支可枚举时，用普通代码或 DAG，例如 ETL、固定审核流程。
- 下一步需要结合自然语言和动态观察决定，且可能循环、追问或调用不同工具时，才需要 Agent。
- 状态图适合“路径动态但状态结构和安全边界可定义”的场景，它不是完全自由运行。
- 我的原则是：**确定性的部分写成代码，只有决策不确定的部分交给模型。**

### 4. LangGraph 中 State、Node、Conditional Edge 如何配合循环决策？

- State 保存消息、工具结果、计数器、审批状态等共享数据。
- Node 是一次确定的计算，例如调用模型、执行工具、校验结果或生成最终答案，并返回状态增量。
- Conditional Edge 读取最新 State，决定跳到工具节点、模型节点、人工审批节点还是结束节点。
- ReAct 循环通常是 `model → 条件判断 → tools → model`；还应在 State 中维护 `step_count`，超过上限
  直接终止，避免无限循环。

### 5. 为什么意图识别不能只靠大模型？如何混用模型和规则？

- 明确、稳定、高风险的条件应由规则处理，例如空城市、非法坐标、写操作权限和金额上限。
- 语义丰富、表达方式多样的意图由模型处理，例如用户到底想查天气还是规划组合行程。
- 可采用“规则前置 → 模型分类 → 置信度或结构校验 → 规则兜底”的分层方式。
- 收益是兼顾灵活性和确定性；不能用模型的自报概率作为唯一置信度，需要用校准集验证。

### 6. 意图歧义或低置信度时如何兜底？

- 缺少关键参数时不猜，返回澄清问题，例如“请问你要查询哪个城市？”
- 多个候选地点差异明显时展示候选，让用户选择，而不是默认第一项。
- 高风险操作即使模型很确定，也必须经过权限检查或 HITL。
- 真实 bad case：用户说“深圳大学天气”，天气工具只支持城市级查询。系统应先明确能力边界，
  不能把校区坐标伪装成工具支持的精确地点天气。

### 7. Agent 项目如何拆职责？产品和开发边界不清时怎么定？

- 产品负责用户目标、风险等级、验收案例、失败时的用户体验；开发负责架构、接口、数据边界、
  可观测性和可靠性实现。
- 先共同写清“输入、输出、允许的工具、不能做什么、成功标准、失败降级和人工审批点”。
- 用固定验收样例和状态图对齐，而不是只讨论抽象需求。
- 任何涉及真实写入、费用、权限和外部消息的操作，都必须明确最终责任人和审计要求。

## 二、上下文工程与记忆

### 8. 超长上下文如何压缩，又不丢关键信息？什么时候触发？

- 不把所有历史原样发送给模型，而是分成近期窗口、结构化长期事实、任务状态和可检索历史。
- 摘要不能只存自然语言，还应单独保留用户约束、已确认参数、未完成动作、工具结果 ID 和来源。
- 触发可以采用 Token 预算，例如上下文达到模型窗口的 60%～70% 时压缩，而不是等到溢出。
- 压缩后做一致性检查：关键实体、数字、权限和未完成任务必须仍能从摘要或状态字段恢复。

### 9. 记忆怎么存、怎么取？长任务如何验证记忆正确？

- 短期记忆是同一 `thread_id` 下的消息和图状态，使用 checkpointer 保存。
- 长期记忆应存结构化事实，并按 `user_id/tenant_id` 做命名空间，附来源、时间和有效期。
- 读取时不是全量注入，而是根据当前任务检索相关事实，并限制条数和 Token。
- 验证需要覆盖：写入后跨轮读取、服务重启后恢复、用户更正后的覆盖、过期失效、不同用户隔离。

### 10. Redis 在 Agent 系统中存什么？不把全量历史喂给模型怎么设计？

- Redis 适合保存短期会话缓存、分布式锁、限流计数、任务进度、幂等键和热点检索结果。
- 权威会话和审批记录更适合持久数据库；Redis 不应是唯一事实来源。
- 上下文采用“最近 N 轮 + 历史摘要 + 检索出的相关片段 + 当前结构化状态”，而不是完整历史。
- 每类内容设置 TTL 和最大大小，敏感内容加密或不进入缓存。

### 11. Checkpoint 如何做断点恢复？状态存在哪里？

- LangGraph 在图执行步骤间保存 State snapshot，并通过 `thread_id` 定位一条执行线程。
- 中断后持久化当前消息、节点状态、待执行操作和 checkpoint 元数据；恢复时用相同 `thread_id`
  和 `Command(resume=...)` 继续。
- 我的 Demo 使用 `AsyncSqliteSaver`，适合单机；生产多实例应换 PostgreSQL 等共享存储。
- 国产算力受限主要影响模型推理部署，不改变 checkpoint 的基本设计；状态应存数据库而不是加速卡显存。

### 12. LangGraph 状态序列化如何做版本兼容？老会话怎么迁移？

- State 必须包含显式 `schema_version`，字段只保存可序列化数据，避免直接持久化客户端、连接或闭包。
- 新增字段提供默认值；重命名或语义变化时写 `v1 → v2` 迁移函数，并保留旧版本读取测试。
- 图定义重大变化时不能盲目恢复旧 checkpoint，可将旧会话标记为只读，或迁移到兼容节点后继续。
- 上线前用历史 checkpoint 回放测试；部署采用双读或灰度，确认迁移成功后再清理旧格式。

## 三、工具、Skills 与 AI Coding Harness

### 13. Tool/Skill 如何注册？模型如何选择工具？

- 工具注册的核心是名称、用途描述、参数 JSON Schema、返回结构和权限/副作用元数据。
- 模型根据系统指令、用户请求、历史消息以及工具名称和 Schema 生成结构化 tool call。
- 框架负责校验并执行调用，再将工具结果作为新消息交回模型；不是框架替模型决定具体工具。
- 描述应写清适用场景和禁止场景，参数用枚举、范围和必填约束减少误调用。

### 14. AI Coding 场景如何把仓库上下文提供给模型？全量还是分层检索？

- 小仓库可以加入目录树和少量关键文件，但真实仓库不应全量塞进上下文。
- 先提供仓库级规则、目录结构和任务相关文件，再用符号搜索、文本搜索、依赖关系和测试失败进行分层检索。
- 修改前读取调用方、被调用方、类型定义和测试；修改后只补充新的 diff、错误和必要上下文。
- 好处是降低 Token 和噪声，避免模型被无关文件干扰；风险是漏取依赖，因此必须结合编译和测试闭环。

### 15. Agent harness 是什么？`AGENTS.md` 和 Skills 怎么用？

- Harness 不是单一模型，而是包围模型的执行系统：上下文装配、文件/终端工具、权限、循环控制、
  状态、Trace、评测和 Guardrail。
- `AGENTS.md` 一类仓库规则用于声明构建命令、代码规范、目录边界和禁止操作。
- Skill 是可复用的任务说明和脚本包，适合把文档生成、部署、代码审查等流程标准化。
- 规则应短而稳定，复杂流程放 Skill；任何说明都不能替代沙箱、权限控制、测试和人工审批。

## 四、RAG 深入问题

### 16. RAG 应按固定大小、语义还是结构切分？Chunk 和重叠怎么选？

- 优先保留文档结构：标题、段落、列表、代码块和表格不能随意截断；超长结构块再做递归切分。
- 固定大小提供硬上限，语义切分提高完整性，因此生产中通常是“结构优先 + 长度兜底”。
- Overlap 用来保留跨边界语义，但过大会产生重复召回和额外存储。
- 当前 Demo 使用 `500/80` 作为基线，不应声称最优；应根据 Recall@K、MRR、答案正确率和 Token 成本调参。

### 17. 粗召回后为什么还需要 Cross-Encoder 重排？候选数怎么定？

- 向量召回分别编码 query 和文档，速度快，但细粒度词序、否定关系和条件匹配可能不够准确。
- Cross-Encoder 把 query 与每个候选一起编码，相关性判断更精细，但计算成本更高。
- 常见链路是先召回 20～100 个候选，再重排后取 3～10 个进入模型；具体数量取决于延迟和文档规模。
- 我的 Demo 尚未实现 Reranker；后续会用标注问题集比较 Recall@K、MRR、最终回答质量和 P95 延迟再决定。

### 18. Agentic RAG 与传统 RAG 有什么区别？Agent 怎么决定查几次、怎么改写 query？

- 传统 RAG 通常是一次“检索 → 生成”；Agentic RAG 增加路由、Query Rewrite、多跳检索、结果评估和再检索。
- Agent 可以先拆解问题，根据首次检索的覆盖度、来源数量、分数和缺失实体判断是否再查。
- 每轮需要记录已用 query，避免同义循环；达到最大检索轮数、Token 或时间预算立即停止。
- Query Rewrite 不能丢失用户约束，应保留实体、时间、范围和否定条件，并用评测验证改写是否提高召回。

### 19. RAG 知识库过期、Top-5 全错，Agent 仍硬编答案怎么治理？

- 文档写入时保存版本、更新时间、有效期和来源，查询时做租户、权限、时间和版本过滤。
- 检索后使用相关性阈值、Reranker 或证据覆盖检查；没有合格证据时确定性拒答，不调用生成模型。
- 回答必须返回来源和版本；高风险领域可要求两条独立证据或人工复核。
- 建立“过期资料、错误 Top-K、冲突资料、无答案”评测集，并监控拒答率、引用正确率和知识新鲜度。

### 20. 如何验证确定性拒答不是只靠 Prompt？

- 先由代码按相似度阈值过滤检索结果。
- 若为空，直接返回固定文本、`grounded=false` 和空来源，不进入 Qwen 调用分支。
- 单元测试注入一个“只要被调用就报错”的假模型客户端，证明低分结果不会触发 LLM。
- 阈值可能造成误拒答，因此需用标注集衡量 Precision/Recall，而不是把 `0.40` 当通用真理。

## 五、可靠性、安全、成本与评测

### 21. 模型失败、工具超时、返回脏数据，Agent 循环如何熔断？

- 每次调用设置超时；只对网络错误、429 和部分 5xx 做有限重试，并采用指数退避和抖动。
- 工具结果先做 Schema 和业务校验，错误以结构化结果返回，不能把异常堆栈直接交给模型。
- 维护总步数、同一工具重复次数、连续失败次数、总时间和 Token/费用预算，任一超限即终止。
- 对持续失败的供应商使用熔断器：关闭期间快速失败或切换降级服务，半开状态用少量请求探测恢复。

### 22. Agent 疯跑、步数爆炸和烧钱，先掐哪三个开关？

1. **立即停止新模型和工具调用：** 取消当前任务，关闭自动重试和后台队列消费。
2. **关闭入口或高风险工具：** 通过 feature flag/kill switch 禁用 Agent 或副作用工具，保留只读降级。
3. **冻结预算并保留证据：** 收紧账户配额和并发，保存 trace、prompt 版本、tool call 与费用数据。

恢复前必须完成根因定位、离线回放和小流量灰度，不能只改 Prompt 后直接全量上线。

### 23. 增加一次 LLM 调用“更准”，如何计算成本和失败率？

- 先定义它改善哪个指标，例如任务完成率从 90% 到 94%，不能只说主观更准。
- 单次成本包括输入/输出 Token、额外工具调用和推理时延；总成本约为 `请求量 × 单次增量成本`。
- 串行链路成功率近似相乘：原流程 99%，新增调用成功率 98%，整体上限约为 97.02%，还未计超时关联。
- 只有质量收益超过成本、P95 时延和可靠性损失，并且可通过缓存、小模型或按需触发优化时才加入。

### 24. Tool Calling 参数校验、命令注入和 SSRF 怎么防？

- Schema/Pydantic 只解决类型和范围，业务层还要校验资源所有权、状态和权限。
- 不把模型参数拼接进 shell；必须执行时使用参数数组、命令白名单、受限工作目录和低权限沙箱。
- URL 工具只允许 `https` 和域名白名单，解析 DNS 后阻止环回、内网、链路本地和云元数据地址，
  重定向后也要重新校验，防止 SSRF。
- 写操作使用幂等键、HITL 和审计日志；密钥永远不进入模型上下文和工具返回值。

### 25. 提示注入有哪些真实场景？Guardrail 在输入输出端分别做什么？

- 场景包括：网页或文档中藏“忽略系统指令”、恶意工具描述、外部 Agent 返回诱导文本、用户要求泄露密钥。
- 输入端：区分指令与不可信数据、来源标记、内容扫描、长度限制、租户隔离和权限检查。
- 工具端：最小权限、参数校验、网络/文件白名单、HITL，防止模型即使被注入也能执行危险动作。
- 输出端：敏感信息检测、引用核验、结构校验和业务合规检查。Guardrail 应分层，不能只靠一个 Prompt。

### 26. Eval、Trace、Guardrail 分别解决什么？为什么不能只靠 Prompt？

- **Eval：** 回答“系统整体是否做对”，用固定数据集测工具选择、参数、召回、忠实度、拒答和成本。
- **Trace：** 回答“这一次为什么错”，记录模型调用、节点、工具、参数、耗时、Token、错误和版本。
- **Guardrail：** 回答“即使模型犯错，哪些事情也不能发生”，在运行时拦截危险输入、输出和工具操作。
- Prompt 只是概率性行为引导；它既不能证明质量，也不能提供逐步证据，更不能替代权限和代码校验。

### 27. LLM-as-a-Judge 放在哪里？如何减少位置和长度偏见？

- 放在离线评测或低风险质量监控层，不作为高风险事实正确性的唯一裁判。
- 先定义评分 Rubric，并提供问题、参考答案、证据和待评回答；输出结构化分数与理由。
- 对成对比较随机交换答案顺序，做 A/B 与 B/A 两次；控制长度或要求裁判忽略文风和长度。
- 用多裁判模型、人工抽检和一致性统计校准；保留版本，避免裁判模型升级后指标不可比。

### 28. 数据意识：数据集规模、埋点和单点回归验证怎么回答？

- 先说明数据来自哪里、多少样本、如何划分、覆盖哪些正常与失败场景，不能只报一个百分比。
- 埋点至少包括 request/thread/run/tool_call ID、模型和 Prompt 版本、节点、延迟、Token、工具状态和错误类型。
- 修复 bad case 后先增加最小单元测试，再加入行为回归集，最后与历史基线比较质量、成本和延迟。
- 我的 Agent 当前有 8 条固定行为案例，适合证明关键路径回归稳定，但不能代表所有真实问题。

### 29. 多模态输入的边界是什么？OCR、图片和视频上下文如何处理？

- 先做 MIME、大小、页数/时长和恶意文件检查，再提取 OCR、图像描述、时间戳与来源坐标。
- OCR 结果是不可信派生数据，应保留原图区域和置信度，关键数字低置信度时请求人工确认。
- 视频按镜头或时间窗抽帧并结合音频转写，不能把整段视频无结构地塞给模型。
- 如果没有多模态评测和业务证据，应明确说“当前项目未实现”，不能因为模型支持图片就宣称系统可靠支持。

## 六、多 Agent 与协议

### 30. Planner 和 Critic 如何分工？Critic 怎么判断幻觉或工具结果不可信？

- Planner 负责拆任务、选择依赖和定义完成条件；Executor 执行；Critic 根据规则和证据检查结果。
- Critic 不应只问另一个模型“对不对”，还要校验 Schema、来源、数值范围、引用覆盖和工具间一致性。
- 对工具错误优先相信确定性状态码和业务校验；对事实回答要求证据可支持具体结论。
- Critic 增加延迟和成本，只有复杂高价值任务才值得；简单流程用代码校验更可靠。

### 31. 多 Agent 主流拓扑：Supervisor、群聊、流水线、层级分别适合什么？

- **Supervisor：** 中心 Agent 分派给专家，控制强、易审计，适合企业任务；中心可能成为瓶颈。
- **群聊：** 多 Agent 共享消息并轮流发言，适合头脑风暴；最容易上下文爆炸和重复讨论。
- **流水线：** 上一步输出作为下一步输入，适合角色明确的生成—审核—发布流程；对动态任务不灵活。
- **层级：** Supervisor 下还有子团队，适合大型任务；治理、追踪和失败恢复最复杂。
- 能用单 Agent + 工具解决时不应上多 Agent。

### 32. 多 Agent 上下文爆炸怎么治理？传全量还是传结论？

- 默认传结构化任务包和结论，不传全部内部对话；内容包括目标、约束、输入引用、产物和未决问题。
- 原始证据存对象存储或共享 Store，通过 ID 按需获取，而不是在消息间复制。
- 每个 Agent 有独立上下文预算、摘要策略和最大轮次，Supervisor 只保留跨角色必要状态。
- 调试系统保留完整 Trace，但执行上下文与审计日志分开。

### 33. A2A 和 MCP 有什么区别？为什么一套系统可能都需要？

- MCP 面向 Agent/模型与工具或数据源，暴露 Tools、Resources 和 Prompts。
- A2A 面向独立、可能内部不透明的 Agent 系统，通过 Agent Card 发现能力，并用 Task、Message、
  Artifact 等对象协作。
- 例如“出行 Agent”可用 MCP 调天气工具，同时通过 A2A 委托“企业差旅 Agent”完成审批。
- 两者互补但都增加复杂度；单体系统内部子 Agent 可直接使用框架原语，不一定需要 A2A。

### 34. 多 Agent 责任如何追溯？坏答案如何定位到节点和工具调用？

- 全链路使用 `trace_id/run_id`，每个 Agent、节点和 tool call 有独立 span，并记录父子关系。
- 记录输入摘要/哈希、输出、模型与 Prompt 版本、工具参数、来源、延迟、Token、重试和状态。
- 最终答案保存引用到具体 evidence ID 和产生它的 Agent/node/tool_call ID。
- 发生问题时可从最终答案反向定位证据、工具结果、模型决策和版本，同时对敏感数据做脱敏。

### 35. LangGraph 子图如何复用？动态注册子 Agent 和热更新怎么做？

- 稳定能力做成输入输出 Schema 明确的子图，由父图像调用节点一样复用。
- 动态 Agent 放在版本化 Registry 中，保存名称、版本、能力、入口、权限和健康状态；任务开始时固定版本。
- 热更新采用新增版本、灰度流量和旧版本排空，不修改正在运行任务所绑定的图定义。
- checkpoint 保存 `graph_version`；旧会话只能恢复到兼容版本，或经过显式迁移后进入新图。

### 36. 技术选型：LangGraph + 自研 Harness、AutoGen、CrewAI 怎么拍板？

- 先比较需求而不是框架热度：是否需要持久状态、HITL、图控制、多 Agent 会话、可观测性和团队语言栈。
- LangGraph 适合需要显式状态、循环、暂停恢复和确定性节点的流程；AutoGen/CrewAI 更强调快速搭建角色协作。
- 自研 Harness 控制力最高，但需要自己承担权限、Trace、评测、升级和运维成本。
- 用 2～3 个真实任务做 Spike，比较任务完成率、P95、Token、调试难度、故障恢复和维护成本后决定。

## 七、HITL、生产工程与算力

### 37. HITL 在 LangGraph 中如何实现？人长期不响应如何超时降级？

- 在副作用工具前 `interrupt`，checkpoint 保存暂停状态，接口返回待审批动作。
- 用户批准后用相同 `thread_id` 和 `Command(resume=...)` 继续；拒绝则把拒绝结果写回图。
- 暂停不能依赖 HTTP 长连接，应返回任务 ID，并通过数据库、轮询或通知系统处理异步审批。
- 设置审批 TTL；超时默认拒绝并释放锁，通知用户重新发起。资金、删除等高风险操作绝不能超时自动批准。

### 38. 画一个企业级研发助手 Agent 分层架构

```text
接入层：Web/IDE/CLI、鉴权、租户、限流
  ↓
编排层：任务路由、状态图、预算、HITL、失败恢复
  ↓
工具层：代码检索、Git、CI、工单、文档、沙箱执行
  ↓
存储层：PostgreSQL、Redis、向量库、对象存储、密钥服务
  ↓
可观测层：Trace、日志、指标、Eval、审计、告警
```

- 工具层执行最小权限，代码运行必须在隔离沙箱。
- 编排状态与产品数据分开，所有层通过统一 ID 关联。

### 39. AI Coding 工程化中哪一步最容易造成生产事故？

- 最危险的不是代码生成，而是**把未经验证的修改自动应用到真实环境**。
- 生成后必须经过 diff 审查、静态检查、单元/集成测试和最小权限沙箱执行，再进入人工审批。
- 发布采用 canary/灰度、健康指标和自动回滚，数据库变更需前向/后向兼容。
- 单测生成、补丁应用和沙箱执行都可能出错，但越靠近部署，爆炸半径越大。

### 40. 国产 MLU 与 CUDA 的栈差异，动态 Shape 对编排层有什么影响？

- CUDA 生态通常围绕 NVIDIA 驱动、CUDA、cuDNN/TensorRT 和成熟算子；MLU 使用对应厂商运行时、
  算子库和推理引擎，例如 MagicMind。模型兼容性、算子覆盖和调优工具不同。
- 动态 Shape 可能触发多套编译配置、额外内存和性能波动；过多长度组合会降低批处理效率。
- 编排层应按输入长度/Shape 分桶、限制最大上下文和并发、预热常用 Profile，并监控 OOM 与 P95。
- 我没有 MLU 实际部署经验，面试时应明确这是架构理解，不能声称做过性能调优。

### 41. 如何建立对新框架的判断力，不会看见新名词就押注？

- 先问它解决的是协议、编排、存储、可观测还是模型能力，避免比较不同层产品。
- 阅读官方文档和最小示例，检查维护活跃度、兼容性、许可证、可迁移性和退出成本。
- 用真实任务做小型验证，必须有基线，并测正确率、P95、Token、故障恢复和调试时间。
- 如果普通函数或固定 DAG 已满足需求，就不引入 Agent 框架；如果框架拿掉后核心能力还在，说明架构边界更健康。

## 八、手撕算法题

### 42. 从非结构化日志流提取意图标签，并去重保序

核心思路是使用哈希集合记录是否出现过，使用列表保持首次出现顺序，时间复杂度 `O(n)`。

```python
import re


def unique_intents(lines: list[str]) -> list[str]:
    pattern = re.compile(r"intent\s*[=:]\s*([\w-]+)", re.I)
    seen: set[str] = set()
    result: list[str] = []

    for line in lines:
        match = pattern.search(line)
        if not match:
            continue
        intent = match.group(1).lower()
        if intent not in seen:
            seen.add(intent)
            result.append(intent)
    return result
```

面试时补充：真实日志解析要考虑 JSON 日志优先、正则失败、流式迭代和内存上限。

### 43. 实现最简 ReAct 循环，并检测循环

不能要求或记录模型的私有思维，只维护可观测的“动作—工具结果”序列。

```python
def run_agent(question, model, tools, max_steps=8):
    events = [{"role": "user", "content": question}]
    seen_calls: dict[tuple, int] = {}

    for _ in range(max_steps):
        decision = model.decide(events)
        if decision.type == "final":
            return decision.answer

        key = (decision.tool, freeze(decision.args))
        seen_calls[key] = seen_calls.get(key, 0) + 1
        if seen_calls[key] > 2:
            raise RuntimeError("detected repeated tool-call loop")

        observation = tools[decision.tool](**decision.args)
        events.append({"tool": decision.tool, "result": observation})

    raise RuntimeError("agent exceeded max_steps")
```

`freeze` 可把字典递归转换成排序元组。生产代码还要加入总时长、Token、费用、连续失败和取消信号。

### 44. 工具依赖 DAG 的最长关键路径与执行顺序

使用拓扑排序；`dist[v]` 表示到节点 `v` 的最长耗时，转移为
`dist[v] = max(dist[v], dist[u] + duration[v])`。有环则不是 DAG。

```python
from collections import defaultdict, deque


def critical_path(nodes, edges, duration):
    graph = defaultdict(list)
    indegree = {node: 0 for node in nodes}
    parent = {node: None for node in nodes}
    dist = {node: duration[node] for node in nodes}

    for source, target in edges:
        graph[source].append(target)
        indegree[target] += 1

    queue = deque(node for node in nodes if indegree[node] == 0)
    topo = []
    while queue:
        node = queue.popleft()
        topo.append(node)
        for nxt in graph[node]:
            if dist[node] + duration[nxt] > dist[nxt]:
                dist[nxt] = dist[node] + duration[nxt]
                parent[nxt] = node
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)

    if len(topo) != len(nodes):
        raise ValueError("dependency graph contains a cycle")

    end = max(nodes, key=dist.get)
    path = []
    while end is not None:
        path.append(end)
        end = parent[end]
    return dist[path[0]], path[::-1], topo
```

复杂度为 `O(V+E)`。执行时同一拓扑层的无依赖工具可以并行，但要受并发和外部 API 配额限制。

### 46. 项目中为什么不能只靠大模型？

- 模型负责自然语言理解和动态工具选择。
- Pydantic/JSON Schema 负责类型和范围，Service 负责字段转换和第三方错误，确定性代码负责来源、
  阈值和展示边界，HITL 负责副作用授权。
- 结论是：**模型做概率决策，代码守确定性边界。**

### 47. 最近半年主动啃过最难的内容是什么？
