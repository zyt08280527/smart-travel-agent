# 项目演示指南

本指南对应2026-10-25的工作区实现，建议用5–8分钟展示核心流程。它是操作脚本，不代表每一步都有真实验收记录；证据边界见[版本状态](VERSION_STATUS.md)。

## 演示前

按[README](../README.md)启动服务。本轮本地试用前端为 `http://127.0.0.1:5173`，后端为 `http://127.0.0.1:8001`；这是开发配置，不是线上地址。确认前端连接正确后端，地图Key可用，模型与高德网络正常。不要在演示中展示密钥或完整.env。

每个主场景新建对话，保留已有会话和行程，不为清场删除用户数据。地点候选不唯一时按实际列表确认，不预设“第一个一定正确”。如外部服务失败，如实展示失败/重试，不用旧结果冒充新查询。

## 1. 已有目的地：单段规划（约1–2分钟）

输入：

> 帮我规划从深圳大学粤海校区到深圳人才公园的出行方案，比较公共交通、步行和驾车，暂时不指定出发时间。

展示左侧对话、右侧候选与地图。点选公交具体候选，再切换步行/驾车，说明手选不改变候选位置，系统推荐和当前选择分开。若需要演示保存，点击保存并完成审批；未指定时间不阻止普通规划或保存。

可讲解：“模型负责理解需求和调用工具；路线来自高德，硬限制先过滤，再用规则评分。用户选哪条，地图和保存就跟随哪条。”

## 2. 多地点需求：完整两段（约1–2分钟）

输入：

> 从深圳大学粤海校区出发，到深圳人才公园停留60分钟，再去深圳湾公园。不能驾车，暂时不指定出发时间。

按站确认有歧义的地点。右侧查看两个分段、60分钟停留和全程耗时；没有具体时间时不应出现编造的到达日期。选择后按需确认保存并重开，展示完整行程快照。结果中的不可行或未知原因应如实保留。

可讲解：“这是固定顺序的完整行程核算，包含交通与停留，不是只回答第一段，也不是自动优化游览顺序。”

## 3. 未定目的地：定位、连续修改与采用（约2–3分钟）

点击“帮我选目的地”→“使用当前位置”，允许浏览器定位，核对地址/精度/时间并确认。若设备拒绝、精度不足或人在深圳以外，明确展示手动选深圳起点的替代流程，不声称定位成功。

设置总时长4小时、停留120分钟、预算100元、不能驾车；不填出发时间，不查天气，不要求已核实当日开放。提交后查看左侧原因、右侧现有馆区候选。

依次输入：

> 我只有两小时。

> 停留改成60分钟。

展示冲突澄清后合并条件，原预算和不能驾车仍保留；没有满足条件的候选可调整条件重试，不宣称必定推荐三个点。点击“规划去这里”后，确认往返两段都以已确认起点出发/返回，尚未自动保存。可从历史重开，展示条件和阶段恢复。

可讲解：“目的地推荐只比较当前三个馆区，按交通、停留和已知费用核算；定位是明确授权后的一次性输入。推荐、选地点和保存是不同步骤。”

## 4. 守护与提醒（可选，另留等待时间）

使用**测试当天、距现在约20分钟后的明确北京时间**规划一条单段或多站点行程。不要复制固定日期。选定并保存后主动开启守护，再进入“行程提醒”；已在30分钟窗口内，等待检查和刷新。外部耗时或队列可能延迟，不能保证演示时刻立即完成。

有结果时展示检查时间、变化原因或数据不足，以及标已读、只读预览和关闭。点击“发起重新规划”才进入新对话，不自动覆盖保存快照；时间已过期时先澄清。没有达到变化阈值也是有效结果，不承诺一定有延误或天气风险。

若只演示5分钟，可只展示任务状态和关闭；**不要把尚未触发的任务说成定时提醒验证成功**。后台重启恢复、三次失败边界和多设备专项属于额外验收，不在本次短演示中自动算通过。
