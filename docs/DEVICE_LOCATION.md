# 目的地推荐的设备定位（2026-10-25）

在“帮我选目的地”的出发点旁新增“使用当前位置”。只有点击后调用浏览器 `navigator.geolocation.getCurrentPosition`，不在打开网站、推荐弹窗或点击目的地时偷偷获取位置。申请一次高精度，定位超时10秒，不复用缓存；前端总等待25秒涵盖地址解析，不做持续跟踪。

定位结果先展示地址、精度和获取时间（北京时间），点击“确认使用此位置”才替换起点并清空旧推荐；在定位或待确认期间不能提交推荐。保留原手动搜索选择方式；拒绝授权、超时、不支持、安全环境不足时提示重试或手动选择，不创建默认深大起点。取消、关闭弹窗、改手动地点或组件卸载后，迟到的定位/地址响应不覆盖当前输入。开启推荐后弹窗关闭仍保留原推荐请求，不因定位清理取消推荐。

`POST /api/places/device-location` 接收WGS84经纬度、精度米和带时区的获取时刻，校验有限数值、范围、精度大于0且不超过500米；获取时间不得早于当前5分钟或晚于当前60秒。500米是首版产品阈值，不是官方标准或定位保证。转换到GCJ-02查询高德逆地理编码，仅深圳区划可用；省市区不符提示手动选择深圳起点，不篡改城市编码。高德转换/解析失败返回503，参数不符422。

不将设备位置吸附到最近POI。返回 `Place` 保留原WGS84坐标，无POI ID，增加 `location_source=device`、`location_accuracy_m`、`location_captured_at`；地址通过既有高德城市服务新增可选formatted_address取得。路线已有WGS84→高德边界转换保持不变，避免把转换后的坐标当WGS84重复转换。客户端位置是设备自报位置，不能用于身份或物理位置认证。

推荐接受有完整定位元信息的深圳设备出发点，原POI点选仍兼容。确认并重新推荐后，原位置与推荐条件一起保存在既有会话状态；点击“规划去这里”沿用该次推荐的完整起点，生成设备位置→馆区→设备位置的往返，不在采用候选时悄悄切换起点。时间/精度是已确认快照，不会在用户后来移动时自动更新；需要重新点击定位、确认并重新推荐。

定位前页面说明坐标会发送至服务端及高德作地址解析；用户确认并提交推荐后随正常推荐历史持久化，不增加独立定位轨迹库、不改旧记录。浏览器定位可能由GPS、Wi-Fi等来源提供，申请高精度并不保证精度。浏览器要求定位权限和安全环境；正式远程使用需HTTPS，本机localhost可用于开发，手机通过普通局域网HTTP访问通常不能使用。参考：[MDN定位接口](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)、[Chrome安全环境说明](https://developer.chrome.com/blog/geolocation-on-secure-contexts-only/)、[高德逆地理编码](https://developer.amap.com/api/webservice/guide/api/georegeo/)。
